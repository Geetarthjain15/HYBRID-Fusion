### C1 - Identifier column in the source dataset

- **Would group by:** a patient/study/series field shipped with the upstream data
- **Evidence:** src/prepare_dataset.py references only ['image', 'label'] from the source parquet (Hemg/Brain-Tumor-MRI-Dataset, file data/train-00000-of-00001.parquet). No identifier column is read, and none is written to disk.
- **Verdict:** REJECTED
- **Reason:** The conversion script consumes only the image bytes and the class label. Even if the upstream parquet carried an identifier, it was not retained in this repository's copy, so it cannot be recovered from what is on disk.

### C2 - DICOM / NIfTI header metadata (PatientID, StudyInstanceUID, SeriesInstanceUID)

- **Would group by:** standard DICOM identifiers
- **Evidence:** Files with medical-imaging extensions: none. Files carrying the DICOM 'DICM' preamble at byte 128: 0. Every image is a re-encoded consumer-format file.
- **Verdict:** REJECTED
- **Reason:** No DICOM or NIfTI file exists in this repository. The dataset is distributed as JPEG, which does not carry DICOM headers. Absence was established by magic-byte inspection of every file, not assumed from the file extension.

### C3 - EXIF / embedded image metadata

- **Would group by:** acquisition timestamp, device, or a custom identifier tag
- **Evidence:** Images carrying any EXIF tag: 0. Embedded info keys present across the corpus: ['comment', 'jfif', 'jfif_density', 'jfif_unit', 'jfif_version'].
- **Verdict:** REJECTED
- **Reason:** No image carries EXIF. The only embedded keys are JFIF density markers, which encode pixel aspect ratio and contain no subject, device or timing information.

### C4 - Sidecar manifest or label file shipped with the dataset

- **Would group by:** a mapping column from filename to patient
- **Evidence:** Non-image files inside the dataset directories: 2 (dataset_clean/split_manifest.json, dataset_clean/split_report.json). Of these, 2 were generated by this project's own deduplication step and contain no patient field.
- **Verdict:** REJECTED
- **Reason:** The dataset ships no sidecar metadata. The only non-image files are artifacts this project created, whose schema is class and split membership, not subject identity.

### C5 - Numeric suffix of internal filenames, e.g. glioma_00243.jpg

- **Would group by:** shared or adjacent numeric index
- **Evidence:** Filename construction is f"{args.out_dir}/{split}/{cls}/{cls}_{i:05d}.jpg", quality=95, iterating df.iterrows() -> i is the pandas row index of the source parquet. The number is therefore the row position in the source parquet.
- **Verdict:** REJECTED
- **Reason:** The index is an export counter assigned by this repository's own conversion script. It encodes position in a dataframe, not a subject. Treating adjacent indices as one patient would fabricate groupings.

### C6 - External-set filename prefix, e.g. Tr-gl_0138_jpg.rf.<hash>.jpg

- **Would group by:** the 'Tr-xx' prefix or the trailing Roboflow hash
- **Evidence:** Distinct filename shapes in the external set: ['Tr-gl_<N>_jpg.rf.<HEX>', 'Tr-pi_<N>_jpg.rf.<HEX>', 'Tr-no_<N>_jpg.rf.<HEX>', 'm<N>-<N>-_jpg.rf.<HEX>']. The '.rf.<hex>' component is a Roboflow export content hash; the 'Tr-' prefix denotes the upstream archive's own train folder.
- **Verdict:** REJECTED
- **Reason:** No dataset documentation available here defines either component as a patient or study identifier. The Roboflow hash is a per-image content digest, so it is unique per image and groups nothing. Promoting an undocumented prefix to a patient key is explicitly out of bounds.

### C7 - Perceptual-hash / near-duplicate clusters

- **Would group by:** images within a dHash Hamming radius
- **Evidence:** Not evaluated. Excluded before inspection by the Phase 2 rules.
- **Verdict:** REJECTED BY RULE
- **Reason:** Visual similarity is not identity. Two slices from one study may be near-duplicates, and so may scans of two unrelated subjects with similar anatomy at a similar slice level. Using similarity clusters as a patient key would assume the conclusion the audit exists to test.

### C8 - Sequential / contiguous numbering blocks

- **Would group by:** runs of consecutive indices
- **Evidence:** Not evaluated. Excluded before inspection by the Phase 2 rules.
- **Verdict:** REJECTED BY RULE
- **Reason:** Contiguity reflects export ordering. See C5: the ordering here is parquet row order, which has no documented relationship to acquisition or subject.

### C9 - Directory structure

- **Would group by:** the folder an image sits in
- **Evidence:** Directory levels observed are split (Training/Testing) and diagnostic class (glioma, meningioma, notumor, pituitary). No subject-level directory exists.
- **Verdict:** REJECTED
- **Reason:** The hierarchy encodes split and class only. It carries no subject level.

### C10 - A documented naming convention from the dataset source

- **Would group by:** whatever the documentation defines
- **Evidence:** 46 repository files inspected for identifier definitions; 19 lines mention identifier-like terms, none of which defines a patient, study or series key for these filenames.
- **Verdict:** REJECTED
- **Reason:** No documentation in this repository, and none shipped with the data, defines a patient/study identifier or a filename convention that encodes one.

## Conclusion

> Patient-level independence cannot be verified from the available dataset metadata.

No group-stratified split is proposed, because there is no key on which to stratify. No GroupKFold, grouped cross-validation or patient-level metric was computed: with no defensible key, any such number would be fabricated.

### Consequences the manuscript must state

1. All reported held-out performance is **image-level**, not patient-level. If several images originate from one subject, they may fall on both sides of a split, and the held-out numbers would then be optimistic by an amount this dataset does not permit anyone to quantify.
2. The duplicate-clean re-split removes near-duplicate **images**. It does not and cannot remove same-subject leakage, because subject identity is unknown. The two are different problems and only the first has been treated.
3. The claim *the split is patient-independent* is prohibited. So is any clinical-readiness claim resting on it.
4. Establishing patient-level independence requires a dataset that ships subject identifiers, or DICOM originals. Neither is available here.
