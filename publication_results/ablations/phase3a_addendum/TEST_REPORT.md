# Phase 3A Addendum - Verifier Test Report

Generated by `src/publication/test_phase3a_addendum.py`.

**32 of 32 tests passed. Status: PASS.**

Every test builds a synthetic run in a temporary directory, breaks exactly one thing, and asserts the verifier rejects it for that reason. The suite also asserts the opposite direction wherever a check could pass by being indiscriminate: that row order does **not** change an alignment verdict, that a correct stored macro-F1 is accepted by the same code path that rejects a wrong one, that a variant which does not depend on gating is **not** labelled with the weak-evidence caveat, and that an honestly reported 'no stored value available' does not fail a run. A suite that only ever rejected things would pass while the verifier rejected everything.

Two tests exist specifically because the verifier was wrong earlier in this phase: `t15` pins the intended-difference sets to the launch specification after a hand-written version incorrectly claimed `vit_branch_only` changes `multiscale`, and `t18` pins the fact that parameter count cannot decide gating, after an attempt to derive it that way.
